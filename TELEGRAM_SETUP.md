# Форма → Telegram

Форма в секції «Замовлення документа» надсилає заявки в Telegram. Токен бота
**ніколи** не потрапляє в `index.html` — інакше будь-хто прочитав би його через
«переглянути код сторінки» і забрав бота собі. Токен живе тільки на сервері,
у файлі `config.php`.

```
браузер  →  send-form.php  →  api.telegram.org
                  ↑
             config.php  (токен, у git не потрапляє)
```

## 1. Створити бота

1. У Telegram відкрити [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Задати назву та юзернейм.
3. BotFather віддасть токен виду `1234567890:AAF…`. **Нікому не пересилати** —
   ні в чат, ні на пошту.

## 2. Дізнатися `chat_id`

1. Створити групу (напр. «Doverka — заявки») і додати в неї бота.
2. Написати в групу будь-яке повідомлення.
3. Відкрити в браузері `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
4. Знайти в відповіді `"chat":{"id":-100…}` — це і є `chat_id`.

`chat_id` сам по собі нешкідливий: без токена в цю групу ніхто не напише.

## 3. Завантажити файли на Hostinger

Набір для заливки збирається командою:

```
node build-deploy.mjs
```

Вона створює теку `deploy/` — рівно те, що має лежати в `public_html/`, і нічого
зайвого. Далі: hPanel → File Manager → `public_html` → Upload → `deploy.zip`
→ розпакувати (або перетягнути вміст `deploy/` по FTP).

**Не заливати нічого іншого з репозиторію.** Усе, що потрапить у `public_html`,
читається ззовні за прямим посиланням: `CLIENT_BRIEF.md` віддав би бриф і ціни,
`documents/` — незаблюрені скани з персональними даними. `build-deploy.mjs` їх
не бере, тому просто користуйтесь ним, а не ручним копіюванням.

## 4. Створити `config.php`

Через File Manager у hPanel створити `public_html/config.php`:

```php
<?php
return [
    'bot_token' => 'сюди токен від @BotFather',
    'chat_id' => '-100xxxxxxxxxx',
    'notify_email' => '',
    'rate_limit_per_hour' => 5,
];
```

Створювати **прямо на сервері**. У git цей файл не потрапляє — він у `.gitignore`.

## 5. Перевірити

Спочатку самодіагностика — відкрити в браузері:

```
https://doverka.eu/send-form.php?selftest=1
```

Має бути `"config_present": true`, `"token_present": true`, `"can_send": true`
і ваш `chat_id`. Токен там не показується — тільки його довжина.

Потім надіслати тестову заявку з сайту. У групу має прийти повідомлення, а
браузер — перекинути на `/thanks`. Якщо ні — дивитись error log у hPanel,
`send-form.php` пише туди причину.

## Що вміє форма

- серверна валідація імені, контакту та згоди на обробку даних;
- контакт приймається як телефон, `@nickname` або e-mail;
- прихована пастка для ботів (поле `website` — людина його не бачить);
- ліміт 5 заявок за годину з однієї IP;
- необовʼязкова копія заявки на пошту (`notify_email`);
- після успіху — редирект на `/thanks` (це ж і є ціль конверсії для реклами);
- повідомлення про помилку ніколи не розкривають токен.

## Безпека

- Токен не пересилати в чаті чи поштою. Якщо витік — у @BotFather зробити
  `/revoke`, отримати новий і переписати `config.php`.
- `config.php` ніколи не комітити.
- Форма прив'язана до `#order` на головній. Сторінка `/order` працює окремо,
  через Tally, і в цей ланцюжок не входить.
